# Research Findings: UCB Logo turtle graphics primitives and patterns

**Status:** Partial
**Researched:** 2026-11-20 (UTC)
**Question:** What repository-documented turtle-graphics primitives, aliases, platform classifications, and reusable Logo patterns should a practical UCB Logo turtle-graphics skill inventory?
**Scope and assumptions:** Read-only workspace inventory of repository help files, the maintained and historical manuals, primitive registrations, C/JS implementations, startup wrappers, demos, and tests. No Logo runtime, browser UI, build, test, external web lookup, or reset-semantics experiment was performed. This report inventories evidence; it does not propose a finished skill outline or duplicate the separate turtle-state investigation.

## Key Findings

- [documented fact, High] UCB Logo is documented as a one-turtle system with positive X to the right, positive Y up, and heading measured clockwise from positive Y; it does not document hardware-style multiple turtles or collision detection. The same section defines uniform color slots 0-7 and initial slots 8-15 ([docs/ucblogo.texi:3443-3482](../../docs/ucblogo.texi#L3443-L3482), evidence **E1**).
- [documented fact, High] Movement/heading primitives and aliases are registered in C: `forward`/`fd`, `back`/`bk`, `left`/`lt`, `right`/`rt`, `setheading`/`seth`, plus `setpos`, `setxy`, `setx`, `sety`, `home`, `arc`, `pos`, `heading`, `towards`, `scrunch`, and `setscrunch` ([init.c:115,127-138,204-217,236,263,285,347,393-404,418-432,448-450,489](../../init.c#L115)). User help and manual describe the same core semantics ([docs/ucblogo.texi:3515-3649](../../docs/ucblogo.texi#L3515-L3649), evidence **E2**).
- [documented fact, High] `xcor` and `ycor` are library procedures, not C primitive-table entries. They are implemented with `first pos` and `last pos`, respectively ([logolib/xcor:3-7](../../logolib/xcor#L3-L7), [logolib/ycor:3-7](../../logolib/ycor#L3-L7), evidence **E3**). This matters to skill classification because their help files call them library procedures.
- [documented fact, High] Pen up/down and paint/erase/reverse are C primitives with short aliases: `pendown`/`pd`, `penup`/`pu`, `penpaint`/`ppt`, `penerase`/`pe`, `penreverse`/`px`. Color/background/size/palette also have C entries; aliases include `pencolor`/`pc`, `setpencolor`/`setpc`, `setbackground`/`setbg`, and `pendownp`/`pendown?` ([init.c:322-341,367-368,410-431](../../init.c#L322-L341), evidence **E4**).
- [documented fact, High] `pen` and `setpen` are library procedures. `pen` outputs a list containing down/up, mode, size, color, and pen pattern; `setpen` reconstructs those fields ([logolib/pen:3-8](../../logolib/pen#L3-L8), [logolib/setpen:3-15](../../logolib/setpen#L3-L15), evidence **E5**).
- [documented fact, High] The manual distinguishes PAINT, ERASE, and REVERSE modes; RGB pen/background inputs use three percentages less than 100; pen size can be one integer or a two-integer list ([docs/ucblogo.texi:4127-4304](../../docs/ucblogo.texi#L4127-L4304), evidence **E6**). Palette entries are hardware-dependent; uniform initial assignments are documented for 0-15, but the exact usable palette range and live behavior should be left platform-specific unless separately tested.
- [documented fact, High] Window/screen and turtle-control primitives are C entries: `clean`, `clearscreen`/`cs`, `wrap`, `window`, `fence`, `showturtle`/`st`, `hideturtle`/`ht`, `setshape`, `textscreen`/`ts`, `splitscreen`/`ss`, `fullscreen`/`fs`, `setscrunch`, `refresh`, `norefresh`, plus queries `screenmode`, `turtlemode`, `shownp`/`shown?`, `shape`, and `scrunch` ([init.c:153-166,205,219-237,258,306,384,403-437,451-464,480-495,507-511](../../init.c#L153-L166), evidence **E7**). The manual describes `clean` as erasing lines without changing turtle state and `clearscreen` as clearing plus home-like centering ([helpfiles/clean](../../helpfiles/clean), [helpfiles/clearscreen](../../helpfiles/clearscreen), evidence **E8**).
- [documented fact, High] Built-in and named shape support is current: `setshape` accepts shape 0/1 or `"triangle`/`"turtle`; `shape` returns `TRIANGLE` or `TURTLE` ([turtleshape.c:30-84](../../turtleshape.c#L30-L84), [helpfiles/setshape](../../helpfiles/setshape), evidence **E9**). The implementation contains only these two shapes and has no dynamic custom-shape primitive in the registration table.
- [documented fact, High] Labels and fills are user-level graphics operations: `label`, `filled`, and `fill` are registered, with `label` under shared C code and `filled` conditionally implemented for `HAVE_WX` or `__EMSCRIPTEN__` ([init.c:206-208,258](../../init.c#L206-L208), [graphics.c:1501-1688](../../graphics.c#L1501-L1688), evidence **E10**). `setlabelheight` and `labelsize` are similarly registered only for `HAVE_WX` or `__EMSCRIPTEN__`, and Web has adapter implementations ([init.c:423,260](../../init.c#L260), [webgraphics.c:242-256](../../webgraphics.c#L242-L256), evidence **E11**).
- [documented fact, High] The maintained manual labels `filled` and `setlabelheight`/`labelsize` as wx-only and `fill` as not portable, but current code guards `filled`, `clickpos`, `setlabelheight`, and `labelsize` for both wx and Emscripten ([docs/ucblogo.texi:3880-3936,4109-4122](../../docs/ucblogo.texi#L3880-L3936), [init.c:157,260,423](../../init.c#L157), [init.c:423](../../init.c#L423), [graphics.c:1501](../../graphics.c#L1501), evidence **E12**). This is a documentation/platform contradiction, not evidence of live parity.
- [documented fact, High] Mouse primitives are `mousepos`, `buttonp`/`button?`, `button`, and guarded `clickpos`; `buttonact` and `keyact` are special variables, not primitive-table entries ([init.c:147-149,157,294,809-814](../../init.c#L147-L157), [helpfiles/buttonact](../../helpfiles/buttonact), evidence **E13**). The manual gives `clickpos` as wx-only, while current shared guards include Web Edition ([docs/ucblogo.texi:4496-4554](../../docs/ucblogo.texi#L4496-L4554), evidence **E14**).
- [documented fact, High] Picture operations are C primitives: `savepict`, `loadpict`, and `epspict` ([init.c:188,276,402](../../init.c#L188)). The manual warns that saved-picture format is not portable and EPS ignores `fill`, erase, and reverse mode ([docs/ucblogo.texi:4424-4482](../../docs/ucblogo.texi#L4424-L4482), evidence **E15**).
- [documented fact, Medium] Palette behavior is split across C and JS: C validates RGB and calls `set_palette`; Web replaces CSS variables in `#logoColors`, and existing SVG lines then reference palette variables ([graphics.c:1169-1244](../../graphics.c#L1169-L1244), [pre.js:833-850](../../pre.js#L833-L850), evidence **E16**). The skill should avoid hard-coding a palette size as portable because hardware/OS-specific availability is explicitly documented.
- [documented fact, High] Reusable sequence and iteration primitives are mixed between C and library: `repeat` is primitive; `for`, `foreach`, `iseq`, `rseq`, `localmake`, `map`, `map.se`, `filter`, `reduce`, and `pen`/`setpen` are library facilities ([init.c:388](../../init.c#L388), [logolib/for:3-28](../../logolib/for#L3-L28), [logolib/foreach:3-25](../../logolib/foreach#L3-L25), [logolib/iseq:3-13](../../logolib/iseq#L3-L13), [logolib/rseq:3-7](../../logolib/rseq#L3-L7), evidence **E17**). These are useful building blocks for polygons, grids, rings, data-driven scenes, and animation updates.
- [direct observation, High] Existing animation demos establish two reusable frame patterns: `animationdemo.lg` draws a sprite once and moves it, while `animationdemo2.lg` saves old position/heading, calls `clean`, redraws one frame, hides or restores turtle state, and advances state ([animationdemo.lg:1-16](../../animationdemo.lg#L1-L16), [animationdemo2.lg:1-21](../../animationdemo2.lg#L1-L21), evidence **E18**). These patterns are demos, not test or reset guarantees.
- [documented fact, High] Web Edition animation is experimental and registered only under `__EMSCRIPTEN__`: `animationstart` and `animationstop` use C/JS bridge functions; `animationact` is an instruction list, while `animationtime` and `animationdelta` are buried Web variables ([init.c:109-111,812-814,883-885](../../init.c#L109-L111), [liblogo.js:75-112](../../liblogo.js#L75-L112), [webgraphics.c:374-385](../../webgraphics.c#L374-L385), evidence **E19**). `animationtime` is milliseconds since page load; `animationdelta` is elapsed since the prior frame, with source records warning that delta may first be large ([.github/skills/ucb-logo-programming/references/web-runtime-reference.md:9-12](../../.github/skills/ucb-logo-programming/references/web-runtime-reference.md#L9-L12), evidence **E20**).
- [documented fact, High] Web startup defines `makesprite` and `setturtlesprite` as Logo procedures over `runjs`; `pre.js` captures `#logoDrawingElements` into an SVG `<symbol>` and sets `#logoTurtleUse` to the symbol ([webstartup.lg:1-6](../../webstartup.lg#L1-L6), [pre.js:1089-1110](../../pre.js#L1089-L1110), evidence **E21**). The one-turtle restriction and SVG symbol behavior are directly described in repository documentation ([.github/skills/ucb-logo-programming/references/web-runtime-reference.md:24](../../.github/skills/ucb-logo-programming/references/web-runtime-reference.md#L24), evidence **E22**).
- [direct observation, Medium] There is no exact source definition or primitive registration for `setturtle`, `setturtleshape`, or `setshaperendering` as a Logo word. `setturtle` appears only in `animationdemo.lg`; `setturtleshape` is a prose-name in `webedition.md`; `setshaperendering` is documented in Web prose but no startup procedure or primitive table entry accompanies it ([animationdemo.lg:5](../../animationdemo.lg#L5), [webedition.md:429-456](../../webedition.md#L429-L456), evidence **E23**). `Module.setShapeRendering` is a JS settings function, not a current Logo word ([pre.js:240-250](../../pre.js#L240-L250), evidence **E24**).
- [documented fact, High] No bundled help files exist for Web-only `animationstart`, `animationstop`, `animationact`, `animationtime`, `animationdelta`, `makesprite`, `setturtlesprite`, `runjs`, or `setshaperendering`. Core turtle words do have help files. This makes `webedition.md` and source/demos the authoritative local evidence for those Web words ([webedition.md:340-445](../../webedition.md#L340-L445), [helpfiles/Makefile.am:3-44](../../helpfiles/Makefile.am#L3-L44), evidence **E25**).
- [direct observation, High] Standalone Web scene files in `contrib/demoscene/` consistently stop prior animation, clear/configure the screen, initialize palette and scene variables, assign `animationact`, and call `animationstart`; each uses named prefixes and `clean` plus frame redraw ([contrib/demoscene/stars.lg:3-24](../../contrib/demoscene/stars.lg#L3-L24), [contrib/demoscene/tron.lg:3-26](../../contrib/demoscene/tron.lg#L3-L26), [contrib/demoscene/tunnel.lg:3-24](../../contrib/demoscene/tunnel.lg#L3-L24), evidence **E26**). They demonstrate scene isolation patterns but do not establish general reset semantics.
- [direct observation, Medium] Acceptance coverage exists for sprite binding but not for a comprehensive turtle primitive suite: `ACC-BRIDGE-004` creates and selects a sprite, while the active Logo suite has commented placeholders for a missing `UnitTests-Turtle.lg` rather than an active turtle suite ([tests/acceptance/bridge.testcafe.js:161-167](../../tests/acceptance/bridge.testcafe.js#L161-L167), [tests/UnitTests.lg:116-137](../../tests/UnitTests.lg#L116-L137), evidence **E27**).

## Options and Trade-offs

- **Portable core plus platform appendix:** a skill can lead with primitive-table entries and move `runjs`, SVG sprites, animation, speech, and device orientation into explicit Web Edition sections. Trade-off: the core stays useful on wx/native builds, but web-only terms need repeated scope labels.
- **Alias-preserving versus canonical-only examples:** listing aliases alongside canonical names improves live compatibility and autocomplete recall; canonical-only wording reduces ambiguity but hides common code such as `fd`, `pu`, `setpc`, and `cs`.
- **Pen snapshot with `pen`/`setpen` versus manual field capture:** `pen`/`setpen` provides one library-level bundle for position-independent pen state, while manual capture of position, heading, visibility, and pen fields makes state intent explicit. Trade-off: the library bundle includes hardware-dependent pattern data and must not be generalized to a complete drawing-state snapshot.
- **Redraw-each-frame versus persistent/moving sprite:** persistent SVG sprite motion is lightweight and centered on the turtle; full-frame redraw through `clean` avoids stale elements and supports line/label/polygon scenes. Trade-off: full redraw may be slower and need smaller scene segment counts; persistent SVG elements use a separate DOM lifecycle.
- **Documented help versus source-backed Web descriptions:** some Web words have no help-file entry, so a skill could link to `webedition.md`, source, or demos. Trade-off: source-backed descriptions are more current but less discoverable than the existing Help dialog.

## Conflicts and Counterevidence

- **wx-only documentation vs shared guards:** maintained prose calls `filled`, `setlabelheight`, `labelsize`, and `clickpos` wx-only, while `init.c`, `graphics.c`, and `webgraphics.c` contain `HAVE_WX`/`__EMSCRIPTEN__` implementations or guards. The report cannot resolve live behavior across platforms without runtime evidence (E11-E12, E14).
- **Web Edition prose names vs executable words:** `setshaperendering`, `setturtleshape`, and possibly misspellings from older prose differ from current source. `setturtlesprite` is the implemented startup wrapper, while `setturtle` appears only in a demo; neither `setturtleshape` nor `setshaperendering` has a Logo definition found (E23-E24).
- **Web Edition list typos/obsolete names:** `webedition.md` lists `animationframact`, `animationdelay`, and `speakoutput` with inconsistent spelling and later examples use `animationact`. The implementation and demos use `animationact`, `animationtime`, and `animationdelta`. The report follows executable registrations and demos, not every list spelling (E19-E20, E25).
- **Manual shape text vs implementation:** the manual and current `turtleshape.c` agree on triangle/turtle shapes and 0/1 numbering. The browser-only sprite mechanism is separate and should not be described as custom built-in shape support (E9, E21).
- **Clean/clear docs vs full reset semantics:** the manual's one-sentence clean/clear descriptions do not establish every field that may change or survive, and the implementation has platform-specific graphics setup. This report deliberately leaves field-by-field semantics to the separate state investigation (E8).
