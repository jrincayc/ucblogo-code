## Plan: Personal Copilot Accounting

Build a local-first accounting CLI for all usage billed to the user's personal Copilot account. Use VS Code/Copilot CLI OpenTelemetry for per-call detail and the official GitHub billing API for account-level credits and monetary reconciliation. Emit versioned machine-readable JSON as the canonical output. Keep measured/reported usage separate from modeled remote energy and emissions; Copilot does not expose server-side kWh or data-center location, so remote CO2e cannot be a measured result.

**Steps**
1. **Confirm sources and account path.** Enable VS Code Copilot OTel file export with content capture off. Check whether the account is billed personally or through an organization; use the documented personal billing endpoint only for personal-billed Copilot. Do not scrape authenticated pages or depend on undocumented Copilot endpoints.
2. **Ingest per-call telemetry.** Parse OTel chat spans/events into normalized records with timestamp, requested/resolved model, input/output tokens, cache-read/cache-creation tokens, reasoning tokens when present, model-call duration, time-to-first-token, session/conversation IDs, and errors. Add Copilot CLI traces when the CLI inherits the OTel settings. Treat `chat` spans as call-level facts and `invoke_agent` as parent/session totals; never sum both as independent token usage.
3. **Reconcile billing and surface coverage.** Query `GET /users/{username}/settings/billing/ai_credit/usage` through authenticated GitHub tooling, retaining date, product, model, SKU, unit type, gross/net quantity, price, discounts, and amounts. Keep the fixed subscription fee, included-credit consumption, and additional paid usage distinct. Report account-level/model-level totals separately from local per-call traces: the personal billing API does not document client or prompt attribution, so unmatched web/cloud-agent activity cannot be assigned per request. Preserve a legacy premium-request adapter only if the account still uses request-based billing.
4. **Add environmental accounting with provenance.** Optionally measure local client-device energy on Linux using available hardware counters (or CodeCarbon), recording whether energy was read or estimated and noting that process attribution is approximate and GPU readings may be machine-wide. Add an isolated remote-inference estimator using explicit, versioned model/token energy assumptions and a range; EcoLogits is a methodology reference, not a Copilot drop-in. Do not infer server energy from elapsed time or dollars, and show remote emissions as unavailable when required inputs are missing.
5. **Define the JSON contract.** Make stdout emit exactly one versioned JSON document by default, with no prose or progress banners. Include `schema_version`, generation time, reporting window, account/surface scope, source coverage, explicit units, measured/reported/estimated classifications, and stable arrays for daily summaries, models, and per-call telemetry. Represent unknown/unavailable values as `null` with a reason; never conflate them with zero. Include estimation method, factor/version, confidence/range, and source provenance. Omit prompts, responses, and identities. Send diagnostics to stderr and use nonzero exit codes for failures; validate output against a checked-in JSON Schema. Keep word counts null/unavailable unless content capture is separately enabled.
6. **Keep the tool standalone.** Do not add it to the UCB Logo application repository by default. Choose a standalone utility location only when implementation is authorized.

**Relevant files and references**
- No existing UCB Logo application files need to change. The future utility is a standalone project outside `/home/jeff/ucblogo-code`; its exact destination is deferred until implementation is authorized.
- VS Code's [OpenTelemetry monitoring guide](https://code.visualstudio.com/docs/agents/guides/monitoring-agents) documents local JSONL/SQLite export, per-call token/model/duration/TTFT attributes, agent/session/tool spans, and content capture being off by default.
- GitHub's [personal AI-credit billing API](https://docs.github.com/en/rest/billing/usage?apiVersion=2026-03-10) documents per-user model/SKU, unit, quantity, discount, and amount data for up to 24 months. The [AI usage guide](https://docs.github.com/en/copilot/how-tos/manage-and-track-spending/monitor-ai-usage) distinguishes included credits, additional usage, and model breakdowns; [model pricing](https://docs.github.com/en/copilot/reference/copilot-billing/models-and-pricing) gives per-million-token rates.
- The [Copilot usage-metrics API](https://docs.github.com/en/rest/copilot/copilot-usage-metrics?apiVersion=2026-03-10) and [field reference](https://docs.github.com/en/copilot/reference/copilot-usage-metrics/copilot-usage-metrics) are an optional organization/enterprise path: daily per-user reports can include AI credits, client/model token totals, prompts/requests, IDE/feature/language, code-generation/acceptance/LOC, and agent/customization/PR metrics. They require the usage-metrics policy and organization/enterprise permissions, are delayed by processing, and cover a bounded history; they are not the personal-account API.
- Local evidence: this VS Code session store is local-only and currently has 103 `GitHub Copilot Chat` session rows, plus a few other agent rows, but its schema has no per-event token-usage table. The current Copilot debug directory has `main.jsonl` and `models.json`; the model catalog includes model/vendor, tokenizer, limits, and rate metadata. Treat raw `main.jsonl` as an unverified, potentially content-bearing format, not a stable dependency. Use OTel instead.
- Community references: [Copilot Usage Tracker](https://github.com/kanalive/github-copilot-tracker) uses a local OTel receiver and rate-card estimates; [Microsoft Copilot Insights](https://github.com/microsoft/copilot-insights) is a self-hosted OTel observability reference in early preview; [Copilot Usage Dashboard](https://github.com/pvjagtap/github-copilot-usage-dashboard) combines OTel usage with cost estimates; [Copilot Carbon Tracker](https://github.com/EdgarasLegus/Copilot-carbon-tracker-extension) estimates carbon using fixed token and grid factors, illustrating why a single point estimate is weak.
- [CodeCarbon](https://docs.codecarbon.io/latest/explanation/methodology/) measures/estimates local CPU/GPU/RAM energy, while [EcoLogits](https://ecologits.ai/latest/) estimates hosted-model API impacts for supported SDKs; neither directly measures GitHub's Copilot inference infrastructure.

**Verification**
1. Use sanitized OTel fixtures for multiple models, cached tokens, subagents, missing attributes, duplicate parent/child spans, and failed calls; verify token totals are counted once and no message content is persisted.
2. Mock personal billing API responses for included credits, discounts, multiple models, dates, and legacy request usage; verify gross/net amounts and subscription cost are reported separately.
3. Validate every report against the versioned JSON Schema. Test stable field names, explicit units, null-versus-zero semantics, deterministic ordering, clean stdout, diagnostics on stderr, and exit codes.
4. Test carbon unit conversions and provenance for measured local energy versus estimated remote energy. Check that estimates are ranges and that missing energy factors produce `unavailable`, not zero or a fabricated figure.
5. After authorization, run a small local VS Code/CLI sample with OTel content capture disabled, then compare per-model/day traces to the official billing report after GitHub's reporting delay. Account for other personal surfaces as billing-only totals where no per-call source exists.
6. On this Linux host, verify RAPL accessibility before claiming local hardware energy is measured; otherwise label it as estimated or omit it.

**Decisions**
- Scope: all personal-account Copilot billing, with per-call telemetry for instrumented VS Code and Copilot CLI; web/cloud-agent surfaces are represented only at the granularity their official account data exposes.
- Output: versioned JSON is the canonical pipeline interface; no human-readable output is mixed into stdout.
- Carbon: report local-device energy separately from modeled remote inference, with confidence and source metadata. Never present remote inference CO2e as measured.
- Privacy: local storage by default; no prompt/response content, identity, network interception, hidden API scraping, or cloud telemetry export unless separately approved.
- Repository boundary: keep this personal tool out of the UCB Logo application repository unless the user later asks to check it in.

**Further Considerations**
- Personal billing endpoints do not document per-surface or per-prompt usage. Exact attribution for GitHub.com, cloud agents, and other personal-account surfaces may remain unavailable even when account-level AI-credit totals are accessible.
- If Copilot is actually organization-billed, the personal billing endpoint will not include it; an organization administrator would need to authorize the matching billing/usage-metrics endpoints.
- Any remote-energy estimate depends on uncertain model, hardware, utilization, cache, PUE, and data-center electricity assumptions; report the assumptions and uncertainty prominently.
